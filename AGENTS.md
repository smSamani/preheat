# Repository guide

- This repo is documented as an Open Knowledge Format v0.2 bundle in `docs/`. Start at `docs/index.md`.
- Any code change must update the matching concept file in `docs/` (`generated.at`, `status`, `stale_after`, content) and add an entry to `docs/log.md`. Frontmatter carries a top-level `author`.
- Results and figures are regenerated by `python -m preheat` and committed together with the code change that alters them. It writes `results.json` (the 84-pair sweep), `diagnostics.json` (separate named checks) and `figures/`. A test fails if the committed JSON differs from a fresh run.
- Dashboard UI files in `preheat/ui/` are maintained by the owner; keep the JSON API shapes in `docs/dashboard.md` stable.
- Every number shown to a user comes from solver output. Model text is never displayed in the dashboard.
- Never edit `evals/heldout.json`; its hash is tested. Do not tune rules on it. A rule change made after seeing its results is logged in `docs/log.md` as a post-held-out change.
- Committed eval reports (`evals/report_rules.json`, `evals/report_replay.json`) must match a fresh run. Regenerate them with the code change that alters them.
- Never edit `preheat/ui/*` without the owner.

Tested with Python 3.15.2 (the pinned NumPy and SciPy need Python 3.12 or newer).

Commands:

```
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m preheat
python -m preheat ask --offline
python -m preheat eval --mode rules
python -m preheat eval --mode replay
python -m preheat web
python -m pytest -q
```
